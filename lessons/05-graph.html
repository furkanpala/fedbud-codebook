Lesson 5

The model as a graph

FedBUD draws the model as a graph. Each attention block and each feed-forward block is a node, and a client's sub-network is a part of this graph.

The idea

Every layer of the model has one attention block, which holds all its attention heads, and one feed-forward block, which holds all its feed-forward neurons. FedBUD draws the model as a graph of points, called nodes, joined by lines, called edges. The graph has one node for the embedding, which turns tokens into numbers, one node for each attention block and each feed-forward block, and one node for the head, which turns numbers back into tokens. So a model with L layers has 2L + 2 nodes, in the order in which the model computes.

Edges join each node to the next node and to the node after that. With these edges, a node sees its neighbors, not only its position in the list. FedBUD then gives every block one action. FedBUD can keep, halve or drop an attention block. It can keep, halve, quarter or drop a feed-forward block. The model skips a dropped block, so the block's input passes on unchanged. The actions of all blocks form the client's configuration, and the kept blocks form the sub-network.

Questions

Question 1

A model has 12 layers. How many nodes does its graph have?

26. Each of the 12 layers gives two nodes, one attention block and one feed-forward block, and the embedding and the head add two more: 2 × 12 + 2 = 26.

Question 2

What happens to the text when FedBUD drops a block?

The model skips the block. Every block adds its result to the text it receives, so without the block the text passes on unchanged. This is why every configuration still runs as it is.

Question 3

Why does FedBUD also join each node to the node two steps ahead, and not only to the next one?

With these extra edges, each node sees more of its neighborhood. The algorithm that reads the graph can then judge a block by the blocks around it, not only by its place in the list. Lesson 7 shows this algorithm.

Summary

    
FedBUD reads the model as a graph with one node per attention block and one per feed-forward block, plus the embedding and the head. Each block gets an action, from keeping it to dropping it, and the actions of all blocks form the client's configuration. Each client gets its own graph, because FedBUD also writes on every node facts about the client, such as its budget and how much each block matters on its data. Lesson 6 shows how FedBUD measures that.
