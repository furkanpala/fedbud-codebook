Federated learning in two minutes

Clients train on their own data, and a server averages what they learned. No data leave a client.

The idea

Federated learning (FL) trains one model across many clients without moving their data. Training runs in rounds, and every round has three steps.

First, the server sends the current shared model to every client. Then each client trains its copy for a few steps on its own data. Finally, the server averages the clients' copies into the next shared model. A client with more examples counts more in this average, a rule named federated averaging[1].

Clients send only the model's parameters to the server and get the average back. The data stay where they are.

Questions

Question 1

What does a client send to the server in one round?

The parameters. The server sees no data point. This is why clinics and companies can take part without breaking privacy rules.

Question 2

Three clients hold 100, 300 and 600 examples. After training, one parameter of their copies has the values 1.0, 2.0 and 3.0. What value does federated averaging give for this parameter?

2.5. The weighted average is (100 × 1.0 + 300 × 2.0 + 600 × 3.0) divided by 1,000, which is 2,500 divided by 1,000.

Question 3

Set the slider to one training step per round, run 20 rounds, and compare with 30 steps per round. Which setting reaches a good line in fewer rounds, and what could go wrong with many steps?

More steps per round usually reach a good line in fewer rounds, because each client learns more before the server averages. With many steps, each client moves toward the points it holds, so the copies drift apart, and their average can be worse than each copy on its own client's points. Real systems balance the two.

Summary

    
In federated learning, clients train copies of one model on their own data, and a server averages the copies every round. The clients learn together while their data stay private. Federated averaging has one requirement that matters for the rest of this course. Every client must hold the same model, so that the server can average the copies parameter by parameter.
